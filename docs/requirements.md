# Техническое задание: аудиоредактор для Android (v1)

Статус: согласовано с пользователем (2 раунда вопросов). Дата: 2026-11-10.
Редакция 2 (2026-11-10): формат M4A по умолчанию для всех сохранений; добавлены FR-31 «Извлечение одним касанием», FR-32 «Зациклить выделение», FR-33 «Автопроверка сохранённого» (одобрено из `docs/backlog.md`).
Рабочее название приложения: «Аудиоредактор» (окончательное — см. «Открытые вопросы»). Ниже `<App>` = название приложения.

---

## 1. Цель и пользователь

**Пользователь:** один человек, автор проекта, на своём телефоне с Android 15+. Не звукорежиссёр, но хочет предсказуемый и точный результат.

**Проблема:** нужно быстро достать звук из видео и сделать простые правки (обрезка, громкость, нормализация, затухания), не загружая файлы в облако и не ставя рекламные приложения.

**Главная функция:** извлечь звук из видео. По умолчанию результат всегда M4A (AAC): AAC-дорожка копируется без потерь, остальные перекодируются. По выбору доступны «как есть» в родном формате и другие форматы (FR-6a).
**Вторая:** простой неразрушающий редактор одного аудиофайла длиной до 30 минут.

**Что значит «готово» (v1):**
1. Выполнены все FR из раздела 3. Приёмочные проверки проходят на телефоне пользователя.
2. Все расчётные модули `:core` покрыты JUnit-тестами на контрольных примерах из раздела 4, и тесты проходят в CI.
3. APK собирается и подписывается в GitHub Actions.

## 2. Основные сценарии

### С1. Извлечь звук из видео (по умолчанию — M4A)
1. Пользователь выбирает видео одним из трёх способов:
   - в приложении: «Галерея» (системный Photo Picker) или «Файлы»;
   - из другого приложения: «Поделиться» → `<App>`;
   - из другого приложения: «Открыть с помощью» → `<App>`.
2. Приложение показывает звуковые дорожки: язык, кодек, число каналов, частота, битрейт, длительность. Если дорожка одна, список пропускается.
3. Главная кнопка — «Сохранить в M4A». Под ней пометка, что произойдёт: «без потерь (копирование AAC)» или «с перекодированием в AAC 192 кбит/с» (FR-6a).
4. Файл сохраняется новым файлом `<имя>_audio.m4a` в `Music/<App>/`, затем автоматически проверяется (FR-33). Появляется сообщение «Сохранено и проверено: <имя>» с кнопками «Поделиться» и «Открыть в редакторе». Перекодирование продолжается в фоне (FR-29).

### С2. Извлечь звук в другом формате
Шаги 1–2 как в С1. Затем «Другой формат…» → выбор: «Как есть (<кодек>, без потерь)» или M4A / Opus / FLAC / WAV с параметрами (FR-24) → прогресс → сохранение → проверка (FR-33). Выбор не запоминается: в следующий раз снова предлагается M4A (Д-13).

### С6. Извлечение одним касанием (FR-31, по умолчанию выключено)
1. В настройках включён переключатель «Извлекать сразу при „Поделиться“».
2. В галерее пользователь нажимает «Поделиться» (или «Открыть с помощью») → `<App>` для видео с одной звуковой дорожкой.
3. Приложение без дополнительных экранов сохраняет звук в M4A по правилу FR-6a и проверяет файл (FR-33).
4. Появляется результат «Сохранено и проверено: <имя>» с кнопками «Поделиться», «Открыть в редакторе», «Другой формат…».

### С3. Отредактировать аудио
1. Пользователь открывает аудиофайл (или видео; тогда берётся выбранная дорожка).
2. Приложение декодирует файл во временный кэш с индикатором прогресса. Волна появляется по мере декодирования.
3. Пользователь слушает, перематывает касанием по волне, масштабирует щипком.
4. Выделяет фрагмент: перетаскиванием краёв или вводом времени.
5. Применяет «Оставить выделенное», «Удалить выделенное», «Громкость», «Нормализация», «Fade in/out». Каждое действие можно отменить и повторить. Для подгонки границ включает «Повтор выделения» (FR-32).
6. Нажимает «Экспорт» → формат (по умолчанию M4A, AAC 192 кбит/с) → сохранение новым файлом → автопроверка (FR-33). Оригинал не изменяется.

### С4. Быстрая обрезка без потерь
1. Открыт файл, выделен фрагмент (только начало и конец, без вырезания середины).
2. «Быстро, без потерь» → приложение показывает фактические границы с учётом кадров сжатого потока и сдвиг относительно выделения (FR-23).
3. Подтверждение → сохранение новым файлом в исходном кодеке (это единственное исключение из правила «по умолчанию M4A»; для AAC результат и так `.m4a`) → автопроверка (FR-33).

### С5. Сохранённые файлы
Экран «Сохранённые» — список файлов, созданных приложением в `Music/<App>/`. Для каждого: «Поделиться», «Открыть в редакторе», «Удалить» (с подтверждением).

## 3. Функциональные требования

### 3.1. Открытие и входные данные

**FR-1. Источники.** Файл открывается тремя способами:
- через Photo Picker (только видео) и через `ACTION_OPEN_DOCUMENT` (видео и аудио);
- через `ACTION_SEND` (Поделиться);
- через `ACTION_VIEW` (Открыть с помощью) для MIME `video/*` и `audio/*`.

Разрешения на чтение хранилища не запрашиваются.
*Проверка:* каждый из трёх способов открывает MP4-видео с телефона. Разрешений `READ_MEDIA_*` / `READ_EXTERNAL_STORAGE` в манифесте нет.

**FR-2. Контейнеры видео.**
- Поддерживаются: MP4, MOV, 3GP, MKV, WebM, MPEG-TS (всё, что читает `MediaExtractor`).
- AVI, FLV, WMV/ASF, а также файлы без звуковой дорожки и с DRM выдают понятное сообщение. Тексты:
  - «Формат AVI не поддерживается. Поддерживаются: MP4, MOV, 3GP, MKV, WebM, TS.»
  - «В этом видео нет звуковой дорожки.»

*Проверка:* набор тестовых файлов (по одному на каждый контейнер плюс AVI) даёт ожидаемый результат. Приложение не падает.

**FR-3. Аудиоформаты на входе.**
- MP3, M4A/AAC (LC, HE-AAC v1/v2, xHE-AAC), WAV, OGG/Opus, OGG/Vorbis, FLAC — системными декодерами.
- WAV разбирается собственным кодом в `:core`: PCM 8/16/24/32 бит int, 32/64 бит float, `WAVE_FORMAT_EXTENSIBLE`.

*Проверка:* 24-битный WAV открывается без потери разрядности. Сэмплы в кэше совпадают с исходными: после перевода во float32 погрешность ≤ 1 младшего разряда 24 бит.

**FR-4. Разрядность декодирования.**
- У декодера запрашивается float-выход (`KEY_PCM_ENCODING = FLOAT`).
- Если декодер отдал 16 бит, а исходник 24-битный (например, FLAC 24 бит), показывается предупреждение: «Телефон раскодировал файл с точностью 16 бит вместо 24. Для максимальной точности используйте WAV.»

*Проверка:* для 24-битного FLAC фактическая разрядность пишется в журнал, а при 16 битах появляется предупреждение.

**FR-5. Выбор дорожки.** Если в видео несколько звуковых дорожек, показывается список: номер, язык, кодек, каналы, частота, битрейт. По умолчанию выбрана дорожка с флагом «по умолчанию», иначе первая.
*Проверка:* MKV с двумя дорожками показывает обе, и выбранная дорожка действительно извлекается (сравнение длительности и кодека).

### 3.2. Извлечение звука из видео

**FR-6a. Формат извлечения по умолчанию — M4A.** Главная кнопка экрана извлечения — «Сохранить в M4A». Что именно она делает, зависит от кодека выбранной дорожки:

| Кодек дорожки | Действие по умолчанию | Результат |
|---|---|---|
| AAC (LC, HE-AAC v1/v2, xHE-AAC) | копирование без перекодирования (FR-6) | `.m4a`, бит в бит, все каналы как есть |
| Любой другой, для которого в телефоне есть декодер (Opus, Vorbis, MP3, FLAC, PCM, AMR, AC-3/E-AC-3 при наличии декодера) | перекодирование в AAC-LC 192 кбит/с (FR-24), сведение каналов по FR-11, частота по FR-24 | `.m4a` |
| Кодек без декодера в телефоне (FR-9) | M4A невозможен: главная кнопка — «Сохранить как есть», с пояснением по FR-9 | родной контейнер по таблице FR-6 |

- Под главной кнопкой всегда видна пометка: «Без потерь: копирование AAC» или «Перекодирование: Opus → AAC 192 кбит/с».
- Если исходник без потерь (FLAC, PCM), добавляется подсказка: «Исходник без потерь. Для архива выберите FLAC или WAV в „Другой формат…“». Если исходник сжатый и не AAC — подсказка о повторном сжатии из FR-24.
- Кнопка «Другой формат…» даёт выбор: «Как есть (<кодек>, без потерь)» по FR-6 или M4A / Opus / FLAC / WAV с параметрами по FR-24.
- Выбор формата не запоминается: при каждом новом сохранении по умолчанию снова M4A (Д-13).

*Проверка:*
- MP4 с AAC → главная кнопка даёт `.m4a`, пакеты совпадают с исходными бит в бит (как в проверке FR-6);
- MKV с Opus → `.m4a`, кодек AAC-LC, номинальный битрейт 192 кбит/с (или ограниченный по Д-14 с показом фактического), длина по FR-25 ± 1 сэмпл;
- MKV с AC-3 на телефоне без декодера AC-3 → главная кнопка «Сохранить как есть», результат `.ac3`, пояснение показано;
- после сохранения в FLAC через «Другой формат…» следующее открытие экрана снова предлагает M4A.

**FR-6. Копирование дорожки без перекодирования («как есть»).** Используется по умолчанию для AAC (FR-6a), а для других кодеков — по выбору «Другой формат… → Как есть» или когда декодера нет (FR-9). Сжатые пакеты копируются бит в бит. Контейнер выбирается по кодеку:

| Кодек дорожки | Файл | Способ записи |
|---|---|---|
| AAC (любой профиль) | `.m4a` | MediaMuxer MP4 |
| Opus | `.ogg` | MediaMuxer OGG |
| Vorbis | `.webm` | MediaMuxer WebM |
| MP3 | `.mp3` | сырой поток кадров |
| AC-3 / E-AC-3 | `.ac3` / `.eac3` | сырой поток кадров |
| DTS | `.dts` | сырой поток кадров |
| FLAC | `.flac` | собственная запись: `fLaC` + STREAMINFO из CSD + кадры |
| PCM (в MOV/MKV) | `.wav` | собственная запись WAV |
| AMR-NB / AMR-WB | `.3gp` | MediaMuxer 3GP |

Все каналы сохраняются как есть (5.1 остаётся 5.1).
*Проверка:* для каждого кодека из таблицы, где есть тестовый файл, полезные данные пакетов в выходном файле побайтно совпадают с пакетами исходной дорожки. Количество пакетов совпадает. Длительность отличается не больше чем на 1 кадр.

**FR-7. Дыры в отметках времени.** При перекодировании и при декодировании в редактор: если отметка времени (PTS) следующего пакета больше ожидаемой более чем на 1 мс, разрыв заполняется тишиной. Длина тишины = разница, округлённая до сэмпла. Если пакеты перекрываются, лишние сэмплы отбрасываются.
*Проверка:* синтетический файл с искусственным разрывом 100 мс декодируется в длину «исходная + 100 мс ± 1 сэмпл».
*Допущение:* при «как есть» пакеты копируются с исходными PTS, тишина не вставляется.

**FR-8. Начальный сдвиг звука относительно видео** в v1 не воспроизводится. Звук начинается с первого сэмпла дорожки.

**FR-9. Кодек без декодера в телефоне** (типично AC-3/E-AC-3/DTS).
- Если системного декодера нет, доступно только «Сохранить как есть». Кнопки редактора и перекодирования неактивны, рядом пояснение: «Этот телефон не умеет раскодировать звук Dolby Digital (AC-3). Его можно сохранить без изменений, но нельзя редактировать или перекодировать.»
- Если декодер есть, файл обрабатывается как обычно.

*Проверка:* на телефоне пользователя для MKV с AC-3 поведение соответствует фактическому наличию декодера (проверка через `MediaCodecList`).

### 3.3. Редактор: подготовка, волна, воспроизведение

**FR-10. Дисковый кэш PCM.**
- Файл декодируется во временный файл в личной папке приложения: float32, чередование каналов, исходная частота, число каналов после сведения (FR-11).
- Перед декодированием проверяется свободное место: нужно `длительность × fs × каналы × 4 байта + 200 МБ`. Если места не хватает, показывается «Недостаточно места: нужно X МБ, свободно Y МБ».
- Кэш удаляется при закрытии файла и при следующем запуске (остатки после сбоя).

*Проверка:* 30 мин, 48 кГц, стерео → кэш 691 МБ ± 1 МБ. После закрытия файла личная папка приложения не содержит кэшей.

**FR-11. Каналы.**
- Моно остаётся моно, стерео — стерео.
- Многоканальный звук (5.1 и т. п.) сводится в стерео в `:core` по ITU-R BS.775 (FR-C5). Сведение декодером по возможности отключается, чтобы получить все каналы.
- Если декодер всё равно отдал стерео, это принимается и пишется в журнал.

*Проверка:* контрольный пример FR-C5.

**FR-12. Волна.**
- Пирамида мин/макс-пиков: базовый уровень 256 сэмплов на точку, каждый следующий уровень ×4. Строится во время декодирования.
- Масштаб щипком: от «весь файл на экране» до «1 сэмпл ≥ 8 px». На максимальном масштабе рисуются отдельные сэмплы.
- После правок пирамида пересчитывается только для затронутого участка.

*Проверка:*
- на файле 30 мин волна прокручивается и масштабируется без видимых рывков (цель ≥ 50 кадров/с, проверяется профилировщиком GPU);
- пик на любом уровне пирамиды равен максимуму `|x|` по соответствующим сэмплам кэша (юнит-тест).

**FR-13. Воспроизведение.**
- Через `AudioTrack` (float). Правки применяются на лету из кэша и списка правок.
- Касание волны перематывает. Курсор синхронизирован по `AudioTrack.getTimestamp()`.
- При уходе приложения в фон воспроизведение ставится на паузу.
- Повтор выделения — FR-32.

*Проверка:*
- задержка от нажатия «Играть» до звука ≤ 300 мс, после перемотки ≤ 200 мс;
- расхождение курсора и звука ≤ 20 мс на 10-минутном файле;
- звучание совпадает с экспортом: рендер в `:core` для воспроизведения и для экспорта — один и тот же код.

**FR-14. Индикатор перегрузки.** Участки, где после правок `|x| > 1,0`, подсвечиваются на волне красным.
*Проверка:* после +12 дБ на сигнале с пиком −6 dBFS подсвечены все участки выше −12 dBFS исходника.

### 3.4. Выделение и правки

**FR-15. Выделение.**
- Перетаскиванием краёв по волне или вводом времени начала и конца в формате `ч:мм:сс.ммм` (часы можно не вводить).
- Внутри позиция хранится в сэмплах: `n = round(t × fs)`, половина округляется вверх.
- Ошибка ввода (конец ≤ начала, выход за длительность, неверный формат) показывается под полем.

*Проверка:* контрольный пример FR-C1.

**FR-16. Неразрушающий список правок.**
- Правки хранятся упорядоченным списком: обрезка, удаление, громкость, fade, нормализация. Рендер применяет их по порядку.
- Отмена и повтор — не менее 100 шагов в пределах сессии.
- После отмены и повтора результат рендера бит в бит совпадает с исходным.

*Проверка:* юнит-тест: случайная последовательность из 50 правок, отмена всех, повтор всех → результат идентичен.
*Допущение:* список правок не сохраняется между запусками (недавние проекты отложены).

**FR-17. «Оставить выделенное» (обрезка)** и **FR-18. «Удалить выделенное».**
- Границы точны до сэмпла.
- Удаление склеивает куски до и после выделения.

*Проверка:* длина результата равна `длина − (конец − начало)` сэмплов для удаления и `конец − начало` для обрезки. Сэмплы вне зон сглаживания совпадают с исходными бит в бит.

**FR-19. Сглаживание стыков.**
- Переключатель «Сглаживать стыки», по умолчанию ВКЛ. Длительность 1–50 мс, по умолчанию 5 мс.
- Применяется на каждой новой границе после обрезки и удаления: затухание в конце куска до границы и нарастание в начале куска после неё.
- Длина файла не меняется. Кривая — FR-C3.
- Если кусок короче 2N сэмплов, N уменьшается до половины длины куска.
- Значения переключателя и длительности сохраняются в настройках.

*Проверка:* контрольный пример FR-C3. При выключенном переключателе сэмплы у стыка совпадают с исходными бит в бит.

**FR-20. Громкость.**
- Усиление в дБ от −40,0 до +20,0, шаг 0,1. Применяется к выделению, а без выделения — ко всему файлу.
- Коэффициент `g = 10^(dB/20)`.

*Проверка:* +6,0 дБ → каждый сэмпл ×1,995262 (относительная погрешность ≤ 1e-6 во float).

**FR-21. Fade in / Fade out.**
- Применяется к выделению: fade in — от тишины до исходного уровня на всём выделении, fade out — наоборот.
- Без выделения: fade in от начала файла, fade out — к концу. Длительность вводится, по умолчанию 3,0 с.
- Кривые: линейная, равной мощности (по умолчанию), логарифмическая. Формулы — FR-C2.

*Проверка:* контрольный пример FR-C2.

**FR-22. Нормализация.** Два режима, по умолчанию «На слух (LUFS)».
- **На слух:**
  - цель −14 LUFS, предустановки −14 / −16 / −23 LUFS;
  - измерение интегральной громкости по ITU-R BS.1770-5;
  - ограничение true peak ≤ −1,0 dBTP.
  - Требуемое усиление `G = цель − измерено`. Если после G true peak превысит −1,0 dBTP, усиление уменьшается до `G' = −1,0 − TP_исх`. Тогда выводится сообщение: «Громкость −14 LUFS недостижима без перегрузки. Достигнуто −15,3 LUFS (пик −1,0 dBTP).» Лимитера и компрессора нет.
- **По пику:** максимальный `|x|` (сэмпловый пик) доводится до −1,0 dBFS.
- Применяется ко всему файлу после предшествующих правок. Усиление пересчитывается автоматически, если изменились предшествующие правки в списке.
- Если файл короче 400 мс или тише абсолютного порога −70 LUFS, режим «На слух» недоступен с пояснением.

*Проверка:* контрольные примеры FR-C4. После нормализации и экспорта в WAV 32 float измеренная громкость = цель ± 0,1 LU (если не сработало ограничение пика), true peak ≤ −1,0 dBTP + 0,0.

### 3.5. Быстрая обрезка без потерь

**FR-23. «Быстро, без потерь».**
- Доступна, если в списке правок только одна обрезка начала и/или конца и нет других правок.
- Работает для источников, которые можно скопировать по FR-6 (аудиофайлы и дорожки видео).
- Пакеты копируются без перекодирования. Границы округляются наружу, по кадрам: начало — к ближайшей предшествующей границе кадра, конец — к ближайшей последующей. Выделенное содержимое никогда не теряется.
- Учитывается задержка кодера исходника. Для MDCT-кодеков (AAC, Opus, Vorbis, MP3, AC-3) перед началом добавляется 1 кадр «разгона», чтобы первый слышимый кадр декодировался правильно.
- Перед сохранением показываются фактические границы и сдвиг, например: «Фактическое начало 00:00.981 (на 19 мс раньше выделения), конец 00:10.005 (на 5 мс позже).»
- Для WAV обрезка точна до сэмпла. Для FLAC — по кадрам FLAC.
- Рядом подсказка: «Нужна точность до сэмпла? Используйте обычный экспорт; для архива выберите FLAC/WAV.»

*Проверка:* для AAC, MP3, Opus фактические границы, показанные пользователю, совпадают с границами декодированного результата ± 1 мс (декодирование результата и сравнение с исходником по корреляции).

### 3.6. Экспорт и сохранение

**FR-24. Форматы экспорта** (MP3 на выходе нет). **Формат по умолчанию для всех сохранений — M4A (AAC-LC, 192 кбит/с)**: экспорт из редактора, перекодирование при извлечении (FR-6a), извлечение одним касанием (FR-31). Остальные форматы выбираются вручную; выбор не запоминается (Д-13). Исключения: «как есть» (FR-6) и «Быстро, без потерь» (FR-23) сохраняют исходный кодек.

| Формат | Файл | Параметры | По умолчанию |
|---|---|---|---|
| **AAC-LC (по умолчанию)** | `.m4a` | 64–320 кбит/с | 192 кбит/с (ограничение по частоте — Д-14) |
| Opus | `.ogg` | 32–256 кбит/с, частота всегда 48 кГц | 128 кбит/с |
| FLAC | `.flac` | 16 / 24 бит | 16 бит (24 бит, если исходник 24-битный) |
| WAV | `.wav` | 16 / 24 бит int, 32 бит float | как FLAC |

- В «Дополнительно» вручную выбираются частота (8–48 кГц для AAC/FLAC; 8–192 кГц для WAV) и разрядность.
- Частота по умолчанию — как в исходнике. Автоматически она меняется, только если формат требует: Opus → 48 кГц; AAC/FLAC при исходнике > 48 кГц → 48 кГц. Об изменении пользователь видит пометку.
- Ресемплинг — FR-C6. Перевод в 16 бит — с дизерингом (FR-C7); 24 бит и float — без дизеринга.
- Если исходник сжатый, а экспорт тоже в сжатый формат, показывается подсказка: «Повторное сжатие немного снижает качество. Для архива выберите FLAC или WAV.»

*Проверка:*
- при открытии диалога экспорта выбран M4A 192 кбит/с, даже если прошлый экспорт был в FLAC;
- для каждого формата файл открывается системным плеером Android и проходит проверку в CI:
  - FLAC: `flac -t` успешно (MD5 из STREAMINFO совпадает);
  - WAV, FLAC: длительность и параметры по `ffprobe` равны заданным.

**FR-25. Точность длины и начала экспортированного файла.**
- WAV и FLAC: декодированный результат совпадает с рендером `:core` бит в бит при выключенном дизеринге (тестовый флаг).
- AAC (`.m4a`): в файле есть edit list (`elst`) с `media_time` = фактическая задержка энкодера и длительностью = числу сэмплов рендера. При декодировании в ffmpeg в CI результат совпадает с рендером по началу и длине ± 1 сэмпл. Взаимная корреляция определяет сдвиг.
- Opus (`.ogg`): pre-skip в OpusHead = задержка энкодера. Гранула последней страницы обрезает хвост до точной длины. Проверка в ffmpeg ± 1 сэмпл.
- Если MediaMuxer не пишет `elst` или гранулу конца правильно, используется собственная запись контейнера MP4/Ogg в `:core` (решение — на этапе плана, после проверки на устройстве).

*Проверка:* тест «туда-обратно» в CI (`:core` + ffmpeg) и на устройстве (декодирование MediaCodec).

**FR-26. Учёт задержки декодера на входе.**
- При открытии AAC, MP3, Opus отбрасываются «разгонные» сэмплы и хвостовое дополнение. Источники: edit list / iTunSMPB, заголовок LAME/Xing (MP3), pre-skip и гранула (Opus).
- Число декодированных сэмплов должно совпадать с номинальной длиной.

*Проверка:* эталонные файлы с известной длиной (созданные ffmpeg/LAME, длина в сэмплах записана в имени теста) декодируются в длину ± 0 сэмплов. При обнаруженном расхождении — ± 1 кадр, и в журнал пишется предупреждение.

**FR-27. Сохранение (трактовка ответа пользователя, см. Д-1).**
- Все результаты автоматически сохраняются новым файлом в `Music/<App>/` через MediaStore, без разрешений на хранилище. Диалога «Сохранить как…» нет.
- Имя файла: `<исходное имя>_<суффикс>.<расширение>`. Суффиксы: `_audio` для извлечения, `_edit` для экспорта из редактора, `_trim` для быстрой обрезки.
- При совпадении имени добавляется ` (2)`, ` (3)` и т. д. Существующие файлы никогда не перезаписываются. Исходный файл никогда не изменяется.

*Проверка:* три экспорта подряд одного файла дают `x_edit.m4a`, `x_edit (2).m4a`, `x_edit (3).m4a`. Файлы видны в системном приложении «Файлы» в папке Music/`<App>`.

**FR-28. «Поделиться»** сохранённым файлом через `ACTION_SEND` с content-URI. Также экран «Сохранённые» (С5): список файлов, созданных приложением, с действиями «Поделиться» / «Открыть в редакторе» / «Удалить». Перед удалением запрашивается подтверждение.
*Проверка:* файл отправляется в мессенджер. Удалённый файл исчезает из «Файлов».

**FR-29. Фоновый экспорт.**
- Экспорт и перекодирование выполняются в foreground service типа `mediaProcessing`. В уведомлении — процент и кнопка «Отменить».
- При первом экспорте запрашивается `POST_NOTIFICATIONS`. При отказе экспорт всё равно работает, но без уведомления, и пользователь получает пояснение.
- Отмена удаляет недописанный файл.

*Проверка:*
- экспорт 30-минутного файла продолжается при выключенном экране и свёрнутом приложении;
- после отмены в `Music/<App>/` не остаётся частичного файла.

**FR-30. Прогресс и отмена** для всех операций дольше 1 с: декодирование, анализ громкости, экспорт.

### 3.7. Дополнительные функции (одобрены из `docs/backlog.md`)

**FR-31. Извлечение одним касанием** (backlog №1).
- В настройках переключатель «Извлекать сразу при „Поделиться“». По умолчанию **выключен**; значение сохраняется между запусками.
- Срабатывает, только если выполнены все условия:
  - файл пришёл через `ACTION_SEND` или `ACTION_VIEW` (не через выбор внутри приложения);
  - это видео (MIME `video/*` или контейнер с видеодорожкой);
  - в нём ровно одна звуковая дорожка.
- Действие: сохранение по правилу FR-6a без экрана выбора дорожки и формата. Для AAC это копирование в `.m4a`, для остальных кодеков — перекодирование в M4A в фоне (FR-29), без декодера — «как есть» с пояснением FR-9. Затем автопроверка (FR-33).
- Итоговый экран: «Сохранено и проверено: <имя>» и кнопки «Поделиться», «Открыть в редакторе», «Другой формат…». Последняя открывает обычный экран извлечения для того же видео.
- В остальных случаях (несколько дорожек, нет звука, аудиофайл, повреждённый файл, переключатель выключен) открывается обычный экран (С1) или сообщение об ошибке по FR-2.

*Проверка:*
- переключатель включён, «Поделиться» MP4 (одна AAC-дорожка) → файл `_audio.m4a` создан без единого дополнительного касания; время для 30-мин видео ≤ 10 с плюс автопроверка;
- то же для MKV с Opus → `.m4a` (перекодирование) с уведомлением о прогрессе;
- MKV с двумя дорожками → открывается экран выбора дорожки, файл не создаётся;
- переключатель выключен → открывается обычный экран С1;
- после переустановки приложения переключатель выключен.

**FR-32. Повтор (зацикливание) выделения** (backlog №2).
- Кнопка-переключатель «Повтор» рядом с «Играть». Значение сохраняется в пределах сессии.
- Если повтор включён и есть выделение, воспроизведение идёт от начала до конца выделения и сразу продолжается с его начала. Если на момент нажатия «Играть» курсор вне выделения, воспроизведение начинается с начала выделения. Без выделения повторяется весь файл.
- Звучит результат с применёнными правками (тот же рендер, что и для FR-13). Границы выделения — в координатах результата после правок.
- Стык цикла: в выходной поток подряд идут последний сэмпл выделения и первый сэмпл выделения, без вставки тишины и без сглаживания (Д-15).
- Если выделение меняется во время воспроизведения, новые границы применяются сразу: если курсор оказался за новым концом, воспроизведение переходит к новому началу.
- Минимальная длина цикла не ограничивается.

*Проверка:*
- юнит-тест рендера: выделение [48 000; 96 000) при 48 кГц, 5 проходов → в потоке ровно 5 × 48 000 сэмплов, и после сэмпла 95 999 сразу идёт сэмпл 48 000, без пропусков и вставок;
- на устройстве: цикл 1,000 с, 60 проходов — курсор каждый раз возвращается к началу, накопленное расхождение курсора и звука ≤ 20 мс (как в FR-13);
- изменение конца выделения во время воспроизведения применяется не позже чем через 200 мс.

**FR-33. Автопроверка сохранённого файла** (backlog №9).
- После любого сохранения (извлечение «как есть», перекодирование, экспорт, быстрая обрезка, одно касание) файл открывается заново из MediaStore и проверяется:
  1. контейнер читается, в нём ровно одна звуковая дорожка;
  2. кодек, частота и число каналов равны заданным;
  3. длина равна ожидаемой с допуском из таблицы ниже.
- Длина определяется полным декодированием с учётом задержки декодера по FR-26. Если декодера нет (например, AC-3 «как есть»), сверяются число пакетов и суммарный объём полезных данных с исходной дорожкой.

| Что сохранялось | Ожидаемая длина | Допуск |
|---|---|---|
| WAV, FLAC (экспорт/перекодирование) | число сэмплов рендера (после ресемплинга) | 0 сэмплов; для FLAC дополнительно MD5 декодированного PCM = MD5 в STREAMINFO |
| AAC (`.m4a`), Opus (`.ogg`) | число сэмплов рендера | ± 1 сэмпл; если по FR-26 действует запасной режим — ± 1 кадр с предупреждением в журнале |
| «Как есть» и «Быстро, без потерь» | число пакетов и байт полезных данных исходной дорожки (выбранного диапазона) | точное совпадение пакетов; длительность ± 1 кадр |

- Успех: «Проверено: длина совпала (00:12:34.567), AAC 48 кГц стерео».
- Ошибка — понятным языком, с цифрами и советом: «Файл записан с ошибкой: длина 00:12:30.000 вместо 00:12:34.567. Попробуйте сохранить ещё раз или выберите WAV.» Файл не удаляется. В «Сохранённых» он помечается значком «не прошёл проверку» (Д-16).
- Проверка выполняется в том же фоновом сервисе, что и сохранение (FR-29), с прогрессом «Проверка…». Кнопка «Пропустить проверку» прекращает только проверку: файл остаётся, и показывается «Сохранено (не проверено)».
- Средний битрейт сжатых форматов (размер × 8 / длительность) сравнивается с заданным. Отклонение больше ± 15 % — только предупреждение, не ошибка.

*Проверка:*
- корректный экспорт WAV/FLAC/M4A/Opus → «Проверено»;
- тест с искусственно испорченным файлом (усечён на 10 %) → понятная ошибка с длиной, приложение не падает, файл помечен;
- «Пропустить проверку» → файл сохранён, отметка «не проверено»;
- время проверки 30-мин M4A ≤ 40 с на телефоне пользователя (цель, уточняется по NFR-7).

## 4. Расчёты: методики, единицы, точность, контрольные примеры

Общие правила:
- Внутри все сигналы — float32, амплитуда в диапазоне [−1, 1] (полная шкала = 1,0). Время — в сэмплах (Long), частота — в Гц. В секунды, мс и дБ значения переводятся только в интерфейсе.
- Накопители для измерений (суммы энергий) — float64.
- Все формулы — в `:core` с комментарием-источником. До кода их проверяет physics-math-reviewer, после — code-formula-auditor.

**FR-C1. Время ↔ сэмплы.**
- `n = round_half_up(t_s × fs)`, обратно `t = n / fs`. В интерфейсе время показывается с точностью до 1 мс.
- Контроль: `1:23.456` при 44 100 Гц → 83,456 × 44 100 = 3 680 409,6 → **3 680 410**. При 48 000 Гц → **4 005 888**.

**FR-C2. Кривые fade.** Нормированное время `x ∈ [0, 1]`, коэффициент fade in `g(x)`; fade out: `g(1 − x)`.
- Линейная: `g = x`.
- Равной мощности: `g = sin(π·x/2)`.
- Логарифмическая (линейная по дБ, диапазон 60 дБ): `g = 10^(−60·(1 − x)/20)` при x > 0; `g(0) = 0`.
- Контроль при x = 0,5: 0,500000 / 0,707107 / 0,031623; при x = 1: 1,0 для всех. Погрешность ≤ 1e-6.
- Дискретизация на N сэмплах: `x_i = i/(N−1)`, i = 0…N−1. Первый сэмпл fade in = 0, последний = исходный.

**FR-C3. Сглаживание стыка.**
- Кривая — приподнятый косинус: `g(x) = 0,5·(1 − cos(π·x))` для нарастания и `g(1 − x)` для затухания.
- `N = round_half_up(d × fs)`.
- Контроль: 5 мс при 48 кГц → N = 240; при 44,1 кГц → 220,5 → **221**. g(0,5) = 0,5.

**FR-C4. Громкость и нормализация.** Источники: ITU-R BS.1770-5 (11/2023), EBU R 128 v5.0, EBU Tech 3341 (тестовые сигналы и допуски).
- K-фильтр: два биквада, коэффициенты для 48 кГц — из BS.1770. Для других частот коэффициенты пересчитываются из аналогового прототипа билинейным преобразованием (метод проверяет physics-math-reviewer и сверяет с коэффициентами для 48 кГц до 1e-6).
- Блоки по 400 мс с перекрытием 75 %. Абсолютный гейт −70 LUFS, относительный −10 LU.
- Громкость: `L = −0,691 + 10·log10(Σ G_i·z_i)`. Веса каналов L/R = 1,0. Измеряется сигнал после сведения в стерео, то есть тот, что уходит в экспорт.
- True peak: передискретизация ×4 при fs < 96 кГц, ×2 при fs ≥ 96 кГц (Annex 2 BS.1770). Результат в dBTP.
- Сэмпловый пик: `20·log10(max|x|)` в dBFS.
- Контрольные примеры:
  - стерео-синус 1 кГц, амплитуда −23 dBFS в обоих каналах → **−23,0 LUFS ± 0,1 LU** (Tech 3341, тест 1); то же при −33 dBFS → −33,0 ± 0,1;
  - моно-синус 1 кГц, 0 dBFS (как один канал) → −3,01 LUFS;
  - тестовые сигналы true peak из Tech 3341 → в пределах допусков документа (+0,2 / −0,4 dB);
  - нормализация по пику: сигнал с пиком 0,5 → коэффициент 0,891251/0,5 = 1,782502; пик результата −1,00 ± 0,01 dBFS (float/24 бит) и ± 0,05 dB (16 бит с дизерингом).
- Ограничение: true peak измеряется до кодирования. После AAC/Opus пики могут вырасти. Это известное поведение, и пользователь видит пометку «пик измерен до сжатия».

**FR-C5. Сведение 5.1 → стерео** (ITU-R BS.775, коэффициенты без нормировки, LFE отбрасывается):
- `L' = L + 0,7071·C + 0,7071·Ls`
- `R' = R + 0,7071·C + 0,7071·Rs`

Возможные значения > 1,0 сохраняются во float и видны индикатором перегрузки (FR-14).
Порядок каналов определяется по маске каналов декодера.
Контроль: только C = 1,0 → L' = R' = 0,7071; только Ls = 0,5 → L' = 0,35355, R' = 0. Другие раскладки (7.1, 4.0, 5.0) сводятся по той же таблице: Lb/Rb как Ls/Rs.

**FR-C6. Ресемплер** (в `:core`, полифазный windowed-sinc).
- Неравномерность в полосе 0–0,45·min(fs_in, fs_out): ≤ 0,1 дБ.
- Подавление выше 0,5·min(fs_in, fs_out): ≥ 90 дБ.
- Задержка компенсируется, начало без сдвига: ± 1 сэмпл.
- Длина результата `round(N_in × fs_out / fs_in)`.

Контроль:
- синус 1 кГц, 44,1 → 48 кГц: ошибка амплитуды ≤ 0,01 дБ, THD+N ≤ −90 дБ;
- синус 23 кГц на 48 кГц → 44,1 кГц: остаток ≤ −90 dBFS;
- 30 мин при 44,1 → 48 кГц: длина ровно 86 400 000 сэмплов.

**FR-C7. Квантование в целые и дизеринг.**
- 16 бит: TPDF-дизеринг ±1 LSB (сумма двух независимых равномерных величин), без noise shaping.
- `y = clamp(round(x·32768 + d), −32768, 32767)`. Для 24 бит то же с 2²³, без дизеринга.
- Контроль: суммарная ошибка (дизер + округление) для TPDF ±1 LSB имеет дисперсию LSB²/6 + LSB²/12 = LSB²/4, т. е. RMS = 0,5 LSB = 1/65536 → **−96,3 dBFS ± 0,5 дБ** (на тишине и на синусе −20 dBFS, ≥ 10⁶ сэмплов). Среднее ошибки = 0 ± 0,01 LSB.
- Значения > 1,0 обрезаются (срез), количество обрезанных сэмплов сообщается перед экспортом (FR-14).

**FR-C8. Пирамида пиков.** Уровень k хранит min/max по блокам 256·4^k сэмплов по каждому каналу. Точность — точное равенство max/min по сэмплам кэша.

## 7. Допущения и открытые вопросы

### Принятые допущения
- **Д-1 (трактовка ответа о сохранении).** Пользователь сказал: «Пусть будет папка самого приложения и всё сохраняется как новый файл там». Трактовка: папка `Music/<App>/` в общем хранилище через MediaStore, чтобы файлы были видны в «Файлах» и оставались после удаления приложения. Сохранение всегда новым файлом, без «Сохранить как…». В приложении есть экран «Сохранённые».
- **Д-2.** Экран «Сохранённые» показывает файлы, созданные текущей установкой приложения. После переустановки старые файлы остаются в папке, но в списке не видны: для этого нужно разрешение `READ_MEDIA_AUDIO`, а его не запрашиваем.
- **Д-3.** Дисковый кэш PCM float32 и пирамида пиков (FR-10, FR-12).
- **Д-4.** Задержки энкодера и декодера обрабатываются явно, с тестом «туда-обратно» (FR-25, FR-26).
- **Д-5.** Свой разбор и запись WAV. Своя запись контейнера FLAC.
- **Д-6.** Ресемплер — собственный, в `:core`, с характеристиками FR-C6. Встроенный ресемплер Android при экспорте не используется. AudioTrack при воспроизведении может пересчитывать частоту сам — это влияет только на прослушивание.
- **Д-7.** Разрывы в отметках времени заполняются тишиной (FR-7). Теги не переносятся.
- **Д-8.** Громкость от −40 до +20 дБ. Индикатор перегрузки и предупреждение перед экспортом о числе обрезанных сэмплов.
- **Д-9.** Нормализация применяется ко всему файлу (не к выделению).
- **Д-10.** Fade без выделения — 3,0 с от начала или до конца файла.
- **Д-11.** Битрейты по умолчанию (AAC 192, Opus 128 кбит/с) одинаковы для моно и стерео.
- **Д-12.** Отмена и повтор — не менее 100 шагов, только в пределах сессии.
- **Д-13 (трактовка нового требования).** Пользователь сказал: «Думаю что лучше сохранять всё в едином m4a формате. (Но при этом иметь выбор сохранить в другом)». Трактовка: M4A (AAC-LC 192 кбит/с) — формат по умолчанию для всех сохранений. AAC-дорожка видео копируется в `.m4a` без потерь, остальные перекодируются. «Как есть» в родном формате и Opus/FLAC/WAV доступны на выбор. Последний выбранный формат **не запоминается**: каждый раз по умолчанию снова M4A.
- **Д-14.** Если 192 кбит/с больше, чем допускает энкодер AAC при данной частоте и числе каналов (например, моно 8 кГц из AMR), берётся максимальный допустимый битрейт. Фактическое значение показывается рядом с форматом.
- **Д-15.** На стыке цикла в FR-32 сглаживания нет: пользователь слышит точные границы выделения. Возможный щелчок на стыке — ожидаемое поведение.
- **Д-16.** Файл, не прошедший автопроверку (FR-33), не удаляется автоматически: решение за пользователем, в «Сохранённых» есть отметка и кнопка «Удалить».

### Открытые вопросы (не блокируют план)
- **ОВ-1.** Окончательное название приложения, имя папки `Music/<App>/` и package name. По умолчанию — «Аудиоредактор».
- **ОВ-2.** Пишет ли MediaMuxer на API 35 edit list для AAC и правильную конечную гранулу для Opus в OGG. Проверить прототипом в начале разработки. Если нет — своя запись MP4/Ogg в `:core` (FR-25).
- **ОВ-3.** Есть ли на телефоне пользователя декодеры AC-3/E-AC-3 и выдаёт ли системный FLAC-энкодер 24 бит. Если нет — свой FLAC-энкодер в `:core` (fixed-предикторы + Rice; бит в бит проверяется через `flac -t`).
- **ОВ-4.** Целевые значения NFR-7 — уточнить после первого замера на телефоне пользователя. Модель телефона пока неизвестна.
