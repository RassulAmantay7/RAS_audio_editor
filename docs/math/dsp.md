## Вердикт: ЕСТЬ ОШИБКИ (некритичные). Формулы в целом верны, но нужно доопределить 9 мест, иначе реализации разойдутся с эталоном

Все формулы требований совпадают с первоисточниками, а числа в контрольных примерах верны. Критических ошибок в формулах нет. Найдены неоднозначности и неверные критерии проверки (pyloudnorm, ffmpeg). Их нужно закрыть ДО кода: решения ниже помечены «**ПРИНЯТО для реализации**».

## Найденные проблемы (по убыванию критичности)

- **[ВАЖНО] П-1. Критерий T8 «расхождение с pyloudnorm ≤ 0,05 LU» неверен без уточнения.** По умолчанию pyloudnorm (`filter_class="K-weighting"`) использует RBJ-приближение (1500 Гц / +4 дБ / Q 0,707 и ФВЧ 38 Гц / Q 0,5), а НЕ коэффициенты BS.1770. Расхождение с правильным измерителем: −0,041 LU на 48 кГц, −0,15 LU на 11 025 Гц, **−0,195 LU на 8 кГц**. Как исправить: сверять только с `pyloudnorm.Meter(fs, filter_class="DeMan")`. С ним наш эталон совпадает до 1e-4 LU во всех случаях (см. таблицу `loudness_ref.py`).
- **[ВАЖНО] П-2. `ffmpeg ebur128=peak=true` не годится как эталон true peak.** (а) При fs = 192 кГц ffmpeg не передискретизирует и даёт −9,0 dBTP вместо −6,0 (тест 16). (б) Выводит значения с точностью 0,1. (в) При резком начале сигнала результат искажается (тесты 15/16: −5,6/−5,4 вместо −6,0). Как исправить: ffmpeg использовать только как грубую проверку I (± 0,1 LU) и TP (± 0,5 дБ) при fs ≤ 96 кГц. Эталон TP — `loudness_ref.true_peak_lin` (Annex 2).
- **[ВАЖНО] П-3. FR-C3: не задана дискретизация кривой стыка.** Если взять `x_i=i/(N−1)`, как в FR-C2, у стыка окажутся два нулевых сэмпла подряд (последний до границы и первый после). **ПРИНЯТО для реализации:** `x_i = (i + 0,5)/N`, i = 0…N−1. Нарастание после границы: `g_up[i] = 0,5(1 − cos(π x_i))`. Затухание до границы — зеркально: `g_down[j] = g_up[N−1−j]` (j = 0 — самый дальний от границы сэмпл). Нулей нет, `g_up[i] + g_up[N−1−i] = 1`. N считается для каждого куска отдельно: `N_k = min(N, floor(len_k/2))`; при N_k = 0 кусок не трогается. Сэмплы вне зон N_k не меняются (бит в бит).
- **[ВАЖНО] П-4. Разбиение на блоки для любых fs.** При fs = 11 025 шаг 100 мс равен 1102,5 сэмпла. **ПРИНЯТО:** `b(i) = floor(i·fs/10)` (целочисленно, в Long). Блок j — это сэмплы `[b(j), b(j+4))`, `z_j = Σy²/(b(j+4)−b(j))`. Учитываются только полные блоки: `b(j+4) ≤ N`, отсюда число блоков `J = max(0, floor(10N/fs) − 3)` (проверять циклом, а не формулой). Для fs, кратных 5 (все стандартные), длина блока ровно 0,4·fs. Это позволяет считать энергию по 100-мс сегментам в double и складывать по 4. pyloudnorm при `round` в числе блоков иногда берёт последний неполный блок. На файлах ≥ 1 с разница < 0,01 LU.
- **[ВАЖНО] П-5. Ресемплер: размер таблицы фаз при «неудобных» fs.** Для стандартных частот 8–192 кГц максимум L = 2560 (11 025 → 192 000): 2560 × 130 = 332 800 коэффициентов float (1,3 МБ), допустимо. Для произвольных fs (например, 44 099 Гц) L может доходить до 192 000, это десятки МБ. **ПРИНЯТО:** если `L·Nt > 2²⁰`, таблица строится на P = 4096 фаз с линейной интерполяцией между соседними фазами (ошибка ядра ≈ (π·0,95/P)²/8 ≈ 7·10⁻⁸, то есть ниже −140 дБ). Иначе таблица точная, на L фаз. Если fs_in = fs_out — побитовое копирование без фильтра.
- **[ВАЖНО] П-6. True peak ×2 при fs ≥ 96 кГц: в Annex 2 есть только фильтр ×4.** **ПРИНЯТО:** для ×2 берутся фазы 0 и 2 того же 48-отводного фильтра. Фаза 2 — это точка посередине между сэмплами, то есть ровно интерполяция ×2. Начальное состояние нулевое. После конца сигнала подаются 11 нулей, чтобы последние сэмплы прошли через все отводы. Итог: `TP = max(пик по фазам, max|x|)`. Без `max|x|` фаза 0 (центральный отвод 0,972) может дать значение ниже сэмплового пика. На 192 кГц оставить ×2, не ×1: при ×1 тест 16 даёт −9,0 вместо −6,0. Это соответствует букве BS.1770 («передискретизация не ниже 192 кГц»), но тест не проходит.
- **[ВАЖНО] П-7. FR-C2 при N < 2.** `x_i = i/(N−1)` делит на ноль. **ПРИНЯТО:** при N ≤ 1 операция ничего не делает (g = 1). UI не даёт ввести fade короче 2 сэмплов.
- **[ВАЖНО] П-8. FR-22: семантика G' < 0 и допуск «≤ −1,0 dBTP + 0,0».**
  (а) Если исходный TP > −1 dBTP, то при любой цели выходит G' < 0, и файл станет ТИШЕ (пример: I = −16, TP = −0,5, цель −14 → G' = −0,5 дБ, итог −16,5 LUFS). Формула требований это и даёт, и сообщение выводится. Нужно подтверждение пользователя, что так и задумано. Альтернатива — `G' = max(0, …)` без гарантии −1 dBTP.
  (б) «+0,0» во float недостижимо буквально: умножение во float32 даёт до ±1 ulp (≈ 5·10⁻⁷ дБ). **ПРИНЯТО:** в тесте допуск TP ≤ −1,0 + 1e-3 dB. TP измеряется ТЕМ ЖЕ измерителем `:core`. По ffmpeg результат может отличаться на ±0,2 дБ.
  (в) Если при экспорте меняется fs (ресемплинг), TP после ресемплинга может отличаться от измеренного до него на десятые доли дБ: межсэмпловые пики другие, а фильтр Annex 2 ошибается на величину от 0 до +0,22 дБ. Рекомендация: в этом случае помечать «пик измерен на исходной частоте», так же как для AAC/Opus.
  (г) В тексте сообщения: минус — U+2212, запятая, одна цифра после запятой, округление половины от нуля, «−0,0» не выводится. Целую цель выводить без дробной части. Эталон: `basic_ref.fmt_db`: «Громкость −14 LUFS недостижима без перегрузки. Достигнуто −15,3 LUFS (пик −1,0 dBTP).»
- **[ЗАМЕЧАНИЕ] П-9. Число −96,3 «dBFS» в FR-C7 верно только в соглашении «dB относительно амплитуды 1,0»** (так считаются все остальные dBFS проекта: сэмпловый пик, LUFS-калибровка). По AES17 (0 dBFS = RMS полношкального синуса) было бы −93,3. Число оставить, но подписать «дБ отн. 1,0». Допуск ±0,5 дБ слишком широк: при 10⁶ сэмплах статистический разброс ≈ 0,002 дБ. Достаточно ±0,05 дБ.
- **[ЗАМЕЧАНИЕ] П-10. Контроль «моно 1 кГц 0 dBFS → −3,01».** BS.1770 задаёт **997 Гц**: результат −3,0103 (48 кГц) и −3,0075 (44,1 кГц). На 1000 Гц получается −3,0036 / −3,0008, а с допуском 0,01 это на грани. Тест писать на 997 Гц, допуск ±0,005. То же в тесте 1 Tech 3341: 1 кГц даёт −22,9933 (а не −23,000) — это свойство K-фильтра, не ошибка.
- **[ЗАМЕЧАНИЕ] П-11. Моно по BS.1770 — один канал с G = 1.** Моно-файл звучит в двух динамиках, но измеряется на 3 дБ тише, чем тот же сигнал как двойное моно. Это по стандарту (так же делают ffmpeg и libebur128). Если пользователю нужно поведение «как Spotify» (двойное моно) — это отдельное решение.
- **[ЗАМЕЧАНИЕ] П-12. FR-C5: раскладки вне таблицы BS.775.** **ПРИНЯТО** (см. `basic_ref.DMX`):
  - BACK_L/R и SIDE_L/R → Ls/Rs (0,7071 на свою сторону);
  - BACK_CENTER → 0,5 на обе стороны (моно-сурраунд делится на Ls = Rs = 0,7071·S, затем ×0,7071 — **сверить с BS.775-4 табл. 2 для 3/1**);
  - FLC/FRC → 1,0 на свою сторону;
  - LFE и LFE2 → 0;
  - TOP_* и прочие биты → 0 с записью в журнал.
  Порядок каналов в чередовании — по возрастанию номера бита маски. Маска 0x41C (LCRS, `CHANNEL_OUT_SURROUND`) — это тоже «4.0», не путать с quad 0xCC. При отсутствии маски — по числу каналов (таблица `DEFAULT_MASK`). Перегрузка: 5.1 со всеми каналами 1,0 даёт 2,414 (+7,7 дБ), 7.1 — 3,121 (+9,9 дБ). Это допустимо по требованию (индикатор FR-14), но такие сэмплы почти наверняка будут у многоканальных исходников.
- **[ЗАМЕЧАНИЕ] П-13. Края ресемплера.** Вне [0, N_in) сигнал считается нулём. При резком начале или конце сигнала возникают переходные процессы. Пример: синус 23 кГц 0 dBFS при 48 → 44,1 даёт −19 dBFS в первых ~66 сэмплах. Это правильное поведение. В тестах FR-C6 остаток мерить, отбросив по T = Nt/2 входных сэмплов (в пересчёте на выход) с каждого края.
- **[ЗАМЕЧАНИЕ] П-14. Фильтр Annex 2 завышает TP на 0…+0,22 дБ** (максимум около 0,25·fs) и практически никогда не занижает (≥ −1·10⁻⁵ дБ на синусах). Для ограничения −1 dBTP это безопасная сторона. На 11 025 Гц синус 1 кГц −23 dBFS даёт TP −22,78.
- **[ЗАМЕЧАНИЕ] П-15. K-фильтр при fs < 32 кГц.** Билинейное сжатие частот около Найквиста искажает полку: на 8 кГц усиление при 3,6 кГц +4,26 дБ вместо ≈ +4,0. Влияние на I для типичной речи — сотые доли LU. Стандарт другого метода не даёт. Принять и записать в журнал методики.

6. True peak — П-6. 48 коэффициентов (фазы 0 и 1; фаза 2 = фаза 1 в обратном порядке, фаза 3 = фаза 0 в обратном порядке) — в `loudness_ref.py`. **Аудитору: сверить все 48 чисел с BS.1770-5 Annex 2 (с. 18–19).** Набор взят из стандарта (все кратны 2⁻¹³, симметрия соблюдена) и проходит тесты 15–23 Tech 3341, но в ходе этой проверки он сверен с PDF только косвенно.

### FR-C6. Ресемплер
- `L/M = fs_out/fs_in` после сокращения на НОД; `ρ = min(1, L/M)`; срез `fcn = 0,475·ρ` циклов на входной сэмпл; переход `Δ = 0,05·ρ`.
- Kaiser: A = 100 дБ, `β = 0,1102·(100 − 8,7) = 10,0613`; `Nt = чётное ⌈(A − 7,95)/(2,285·2π·Δ)⌉`; T = Nt/2. Отсюда Nt = 130 при повышении частоты, 140 для 48 → 44,1, 514 для 192 → 48, 3078 для 192 → 8.
- Ядро: `h(τ) = 2fcn·sinc(2fcn·τ)·I0(β·√(1−(τ/T)²))/I0(β)` при |τ| ≤ T. sinc(0) = 1.
- Выход m: `P = m·M` (Long), `n0 = P div L`, `p = P mod L`, `μ = p/L`; `y[m] = Σ_{k=−(T−1)}^{T} x[n0+k]·h(μ−k)`. Это нуль-фазовая схема: y[0] стоит ровно во времени x[0], **компенсировать задержку не нужно**. Проверено: центр масс импульса совпадает с n0·fs_out/fs_in до 10⁻¹¹ сэмпла.
- `N_out = (2·N_in·L + M) div (2·M)` (round half up, целочисленно).
- Таблица фаз L × Nt считается в double и хранится во float. Накопление — в float или double (обе версии укладываются в −90 дБ; double надёжнее).
- Потоковая реализация: держать хвост T входных сэмплов. На последнем блоке дополнять нулями.
- Полученные характеристики: неравномерность ≤ 1,6·10⁻⁴ дБ (норма 0,1); подавление ≥ 100,2 дБ (норма 90) на всех проверенных парах.

### FR-C7. Квантование
- ГСЧ SplitMix64 (контракт бит в бит с Python). Порядок: кадр за кадром, внутри кадра канал за каналом, на каждый сэмпл два числа: `d = u1 − u2`.
- `y16 = clamp(floor(x·32768.0 + d + 0.5), −32768, 32767)` — в double. 24 бит: `clamp(floor(x·8388608.0 + 0.5), …)`, без дизеринга.
- Сид: в тестах фиксированный. В продукте — любой (например, nanoTime), записывать в журнал.
- Счётчик обрезанных сэмплов считается по `|x| > 1,0` ДО дизеринга. Иначе дизер на сэмплах около 0 dBFS даст ложные срабатывания.

## Границы применимости
- Измерение громкости: BS.1770 откалиброван на 48 кГц. Для fs 8–24 кГц из-за деформации частот при билинейном преобразовании ошибка на ВЧ-полке до +0,26 дБ около Найквиста, на I — сотые доли LU (П-15). Сигналы > 0 dBFS (после +20 дБ) измеряются корректно (float).
- Интегральная громкость не определена для < 400 мс (нет полного блока) и при всех блоках ≤ −70 LUFS.
- True peak: погрешность фильтра Annex 2 от 0 до +0,22 дБ. Значение до кодирования; после AAC/Opus/ресемплинга пик может вырасти.
- Ресемплер: полоса 0–0,45·fs_min ровная (±0,0002 дБ). Полоса 0,45–0,5·fs_min переходная (там ослабление растёт от 0 до 100 дБ). Это не ошибка, а следствие спецификации.
- TPDF ±1 LSB делает первые два момента ошибки независимыми от сигнала. Шум белый, −96,33 дБ отн. 1,0 (без noise shaping).
- Сведение без нормировки: возможна перегрузка до +9,9 дБ (7.1), сохраняется во float.
